# 依赖与来源（本项目用到了什么）

本仓库**不包含**任何上游项目的完整源码，只包含「为发送语音条而新增/修改的部分」。
要把它接到自己的环境里，需要先有下面这三个项目。

---

## 1. `sourcepro5/WeChatAgent` —— 宿主（MIT）

- 地址：https://github.com/sourcepro5/WeChatAgent
- 许可证：MIT（`LICENSE` 文件注明 `Copyright (c) 2026 Derpyu520 and qq-bridge / QSH contributors`）
- 规模：约 3.9 MB、1170 stars、主语言 JavaScript
- 作用：微信/QQ 机器人的宿主 —— hook 覆盖层、构建脚本、DSH 插件、桌面控制台
- 本机对应目录：整个 `H:\wx\data\workspace` 就是这个仓库的部署形态

### 我们用到的部分

| 用到的东西 | 位置 | 说明 |
|---|---|---|
| hook 覆盖层源码 | `scripts/native-hook/` | `wechatagent_hook.cpp`、`file_sender.cpp`、`sticker_sender.cpp`、`deferred_init.cpp`、`http_server.cpp` 等；本项目的补丁就打在它们身上 |
| 构建脚本 | `scripts/build-hook.ps1` | 把上游 hook 源码 + 覆盖层合并编译成 `version.dll`；本项目另存了一份 `build-hook-local.ps1`，仅把 `PlatformToolset` 改成与本机 VS 匹配 |
| DSH 插件 | `packages/dsh-social-bridge-plugin/` | 微信会话的上下文注入、工具策略、文件收发；本项目的 `/SendVoiceMsg` 路由就是加在它加载的 hook DLL 里的 |
| 桌面端 / 控制台 | `apps/console-desktop/`、`public/console/` | 启停服务、改配置、看日志 |
| 人格 / 记忆 / 会话 | `roles/`、`state/` | 本项目只读取，不上传 |

### 本项目的改动（仓库里以 patch 形式提供）

| 补丁 | 打在哪个文件 |
|---|---|
| `patches/wechatagent_hook.live.patch` | `scripts/native-hook/wechatagent_hook.cpp` —— 注册 `POST /SendVoiceMsg` 路由 |
| `patches/wechatagent_hook.probe.patch` | 同上 —— 初始化只读探针 |
| `patches/build-hook-local.live.patch` | `scripts/build-hook-local.ps1` —— 把 `voice_sender.cpp` 纳入编译 |
| `patches/build-hook-local.probe.patch` | 同上 —— 把 `voice_probe.cpp / .asm` 纳入编译 |

> `src/voice_sender.*`、`src/voice_probe.*` 是本项目新增的文件（不是上游的），可以直接拷进
> `scripts/native-hook/` 后按上面的补丁接线。

## 2. `Derpyu520/qq-bridge` —— 桥接核心（MIT，已 vendored 进 WeChatAgent）

- 地址：https://github.com/Derpyu520/qq-bridge
- 定位：QQ（SnowLuma OneBot v11）与 DeepSeek Harness agent 之间的桥接（社交模拟、安全 MCP 工具、口癖学习）
  （**约 2012 stars、12 MB**；许可证文件内容为 MIT，GitHub 因文件格式标记为 `NOASSERTION`。代码同时被 WeChatAgent 以 `components/qq-bridge` 的形式内置）
- 许可证：MIT（随 WeChatAgent 一起声明）
- 本机对应目录：`H:\wx\data\workspace\components\qq-bridge`
- 运行时形态：独立 node 进程 `components/qq-bridge/src/social-bridge.js`（桥接端口 11229 / 回执 5031）

### 它负责什么

微信群消息的**决策与投递流水线**：收消息 → 合并批次 → 调模型 → 解析发送协议 → 发表情/文字/文件 → 等回执。

### 我们用到的部分（本项目未上传，仅说明位置）

| 文件 | 作用 | 本项目是否改过 |
|---|---|---|
| `src/core/social-engine.js` | 消息接收、批次、决策、发送、冷却 | ✅ 改过：表情候选提示里加了「不要用 `[表情:描述]`、不要调 `send_meme`」 |
| `src/core/decision-format.js` | 解析模型输出（`RESPOND:` / `[STICKER:]` / SILENT） | ✅ 改过：把 `[表情:…]` 判为非法标记，触发格式修正；兜底剥离 |
| `src/core/sticker-policy.js` | 表情候选选择 | ❌ |
| `src/core/message-buffer.js` | 消息缓冲/去重 | ❌ |
| `src/core/media-outbox.js` | 媒体发送队列 | ❌ |
| `src/core/wechat-events.js` | 微信事件归一化 | ❌ |
| `src/core/proactive-engine.js` | 主动发言调度 | ❌ |
| `src/social-bridge.js` | 桥接进程入口 | ❌ |

> 这两处改动是为了解决「她调用 DSH 网页表情工具、发出 `[表情:描述]` 纯文本」的问题，
> 与语音条功能无关，所以**没有包含在本仓库**；想复刻语音功能不需要动 qq-bridge。

## 3. `aixed/WeChat-Hook` —— hook 底座源码（**无许可证，不随本仓库分发**）

- 地址：https://github.com/aixed/WeChat-Hook
- 许可证：**无**（仓库没有 LICENSE 文件，GitHub API 返回 `license=无`）
- 本机对应目录：`H:\wx\data\workspace\components\WeChat-Hook`
- 获取方式：WeChatAgent 的 `build-hook.ps1` 要求使用者**自行下载**该仓库到 `components/WeChat-Hook`，再叠覆盖层编译

### 为什么本仓库不包含它

- 上游没有许可证 → 默认「保留所有权利」，原样转载有版权风险；
- 且它和 WeChatAgent 的覆盖层是「底座 + 定制」的关系，单独传上去也无法直接编译。

### 它提供什么（本项目依赖的部分）

| 用到的东西 | 在本机的位置 | 说明 |
|---|---|---|
| `send_message` / `BuildSendParam1` / `BuildSendParam2_Image` | `components/WeChat-Hook/src/wx_send.cpp` | 发送调度的底座实现；`0x1677A30` 这类 RVA 就在这套代码的上下文里 |
| `version.dll` 代理与注入框架 | `src/version_proxy.cpp`、`dllmain.cpp`、`minhook/` | 负责把模块加载进微信进程 |
| HTTP 框架 | `include/httplib.h`、`src/http_server.cpp` | `/SendVoiceMsg` 等路由跑在它上面 |
| 工程文件 | `x64_Version_dll.vcxproj`、`version.def` | 编译成 DLL 的工程定义 |

> 复刻步骤：先 `git clone https://github.com/aixed/WeChat-Hook` 到 `components/WeChat-Hook`，
> 再按 WeChatAgent 的 `build-hook.ps1` 叠覆盖层，最后打本仓库的补丁。

## 4. 本项目自己新增的文件

| 文件 | 说明 |
|---|---|
| `src/voice_sender.cpp/.h` | 语音条 live 实现（工厂 + 构造 + send_message） |

| `docs/*` | 方法、风险、依赖说明 |
| `patches/*` | 接到 WeChatAgent 覆盖层的补丁 |
